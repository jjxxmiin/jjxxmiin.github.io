Fooocus는 세부 extension을 먼저 조립하기보다 prompt, style, model을 빠르게 골라 image를 만들고 싶은 사용자에게 맞는 Stable Diffusion 기반 interface입니다.

원문은 Linux GPU server와 Conda를 사용한 2024년 실행 기록입니다. Repository dependency와 entry script는 바뀔 수 있으므로 아래 명령을 현재 버전의 보장된 설치법으로 보지 말고, 원문 환경을 재현하는 출발점으로 사용해야 합니다.

## Fooocus를 고를 기준은 설정 자유도보다 첫 결과입니다

Fooocus는 Stable Diffusion의 offline, open-source 성격과, manual tweaking을 줄이고 선택에 집중하는 interface를 결합하려는 도구로 소개됩니다. “Non-cherry-picked”를 강조하며 여러 번 prompt를 고치고 좋은 sample만 추리는 부담을 줄이는 방향입니다.

반대로 모든 sampler, extension을 세밀하게 조합해야 하는 사용자는 단순화된 기본값이 답답할 수 있습니다. 처음 image를 빨리 만들고 preset, style을 고르는 일이 우선인지, 내부 parameter를 모두 통제하는 일이 우선인지가 선택 기준입니다.

## 원문의 Linux 설치는 Conda 환경을 만듭니다

원문 명령은 repository를 clone하고 제공된 environment file과 pinned requirements를 차례로 설치합니다.

```bash
git clone https://github.com/lllyasviel/Fooocus.git
cd Fooocus
conda env create -f environment.yaml
conda activate fooocus
pip install -r requirements_versions.txt
```

이 명령은 Git, Conda와 호환 GPU driver가 이미 준비됐다는 전제입니다. Dependency 설치와 model download에 필요한 저장 공간도 별도로 확인해야 합니다. `environment.yaml`과 `requirements_versions.txt`를 동시에 적용하므로 충돌이 나면 임의 upgrade보다 repository가 의도한 version부터 확인합니다.

원문 실행 entry는 다음과 같습니다.

```bash
conda activate fooocus
python entry_with_update.py
```

Anime와 realistic 기본 설정은 각각 `--preset anime`, `--preset realistic` option으로 실행했습니다. 이 script 이름과 preset 지원 여부 역시 원문 시점 기준입니다.

## 첫 화면에서는 네 영역만 구분하면 됩니다

기본 화면은 prompt 입력을 중심으로 단순하게 보이고, 필요할 때 Input image와 Advanced를 엽니다.

![Fooocus 첫 화면](/assets/img/post_img/fooocus/1.png)

Input image에는 Upscale or Variation, Image Prompt, Inpaint or Outpaint, Describe 기능이 정리돼 있습니다. 기존 image를 바꾸거나 확장할 목적이라면 text prompt만 반복하기 전에 이 영역을 고르는 편이 맞습니다.

Advanced에서는 Setting, Style, Model, Advanced 하위 설정을 다룹니다. Image size, 미리 정의된 style과 model을 바꿀 수 있고, style에 pointer를 올려 sample을 확인하는 흐름이 원문 사용기의 장점이었습니다.

![Fooocus Advanced 화면](/assets/img/post_img/fooocus/3.png)

Custom checkpoint는 원문이 안내한 models/checkpoints 위치에 둔 뒤 interface에서 model을 바꾸는 방식입니다. 실제 checkout의 정확한 상대 경로와 지원 format은 사용 중인 repository 구조를 확인해야 합니다.

## 편리함을 품질 보장으로 확대하지 않습니다

원문 사용기에서는 짧은 “perfume” prompt도 좋은 결과를 냈고, custom model과 미리 정의된 style, size 선택이 편했다고 평가했습니다. 하지만 한 prompt의 sample은 일반적인 품질 benchmark가 아니며 “어떤 설정에서도 문제없다”는 보장이 될 수 없습니다.

설치 확인은 단계적으로 하는 편이 좋습니다. 기본 preset으로 한 장을 만들고, image size를 바꾼 뒤, Input image 기능 하나를 시험하고, 마지막에 custom checkpoint를 추가합니다. 한 번에 model, style, advanced option을 모두 바꾸면 실패 원인을 찾기 어렵습니다.

Fooocus의 장점은 조정 항목이 전혀 없다는 데 있지 않습니다. 자주 쓰는 선택을 interface와 preset으로 앞에 배치해 첫 결과까지의 부담을 줄인다는 데 있습니다. 세밀한 재현이 필요하면 최종 prompt, preset, style, model과 image size를 함께 기록해야 합니다.

## 설치를 어떤 단계로 확인하나요?

Clean environment에서 repository가 요구하는 Python과 package version을 먼저 설치하고 GPU가 framework에서 보이는지 확인합니다. 기본 preset의 model download가 완료되고 한 장을 생성한 뒤에 custom checkpoint와 input 기능을 추가합니다. 모든 옵션을 한 번에 켜면 dependency, VRAM과 model format 중 원인을 찾기 어렵습니다.

Disk에는 environment, base model, VAE와 output 여유를 포함하고 network 중단 뒤 incomplete file을 처리합니다. Server에서 UI를 외부에 공개할 때 authentication과 bind address도 별도 검토합니다.

## 기능 실패를 어떻게 분리하나요?

Text-only 기본 image, size 변경, variation, inpaint와 custom checkpoint를 같은 seed, 기본 model에서 하나씩 시험합니다. Out-of-memory는 image size와 model별 peak VRAM을 기록하고 무작정 package version을 바꾸지 않습니다. Input image의 color, orientation과 mask 경계도 확인합니다.

## 품질 비교에 무엇을 남기나요?

한 장의 좋은 sample 대신 고정 prompt 묶음과 seed에서 artifact, prompt adherence와 생성 시간을 비교합니다. Preset은 여러 내부 설정을 바꿀 수 있으므로 이름과 repository revision을 기록합니다. 단순함과 세부 통제 가운데 실제 workflow 시간을 기준으로 도구를 선택합니다.

## Preset을 바꿀 때 무엇이 함께 달라지나요?

Preset은 checkpoint뿐 아니라 style, resolution과 내부 default를 함께 바꿀 수 있으므로 화면에 보이는 이름만 기록하지 않습니다. 같은 prompt와 seed로 preset 전후 metadata를 export해 어떤 값이 달라졌는지 비교합니다. Custom model이 요구하는 VAE, clip과 권장 resolution도 확인합니다.

## 오래 실행할 때 어떤 실패를 보나요?

여러 image 생성 뒤 GPU memory가 계속 늘어나는지, queue 취소와 browser reconnect에서 작업 상태가 맞는지 확인합니다. Output directory 용량, filename 충돌과 prompt metadata 보존 정책을 정합니다. 공개 server에는 arbitrary file upload, model path와 update script 권한을 제한합니다.

## 선택이 맞았는지 어떻게 판단하나요?

첫 설치부터 원하는 결과와 재현까지 걸린 시간, 실패 수정 횟수를 기록해 세밀한 WebUI와 비교합니다. Fooocus가 감춘 옵션을 실제로 자주 수정해야 한다면 단순 interface 이득이 줄어듭니다. 반대로 preset만으로 요구가 충족되면 extension 유지 비용을 피할 수 있습니다.

## 자주 남는 질문

### Fooocus는 어떤 사용자에게 잘 맞나요?

Sampler와 extension을 세밀하게 조립하기보다 preset, style, model로 첫 image를 빠르게 만들려는 사용자에게 맞습니다.

### 원문의 설치 명령을 현재도 그대로 실행하면 되나요?

보장할 수 없습니다. 2024년 기록이므로 현재 repository 문서와 GPU driver, dependency, entry script를 확인해야 합니다.

### 생성 결과를 재현하려면 prompt만 저장하면 되나요?

아닙니다. Preset, style, checkpoint, image size, seed와 사용한 input image 및 advanced option도 함께 기록해야 합니다.
